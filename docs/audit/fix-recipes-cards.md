# Рецепты правок: обрезанные описания карточек и заголовок ГРК за краем

Разведка для Claude Code (QWEN-06 §Б). Ничего не чинил: `src/v3-polish.css` и
`src/design-system.css` — его файлы. Здесь — где именно сидит правило, что будет,
если поменять, и что я за этим реально измерил (в браузере, через `addStyleTag`,
без правки дерева).

## Сначала поправка к собственному отчёту QWEN-05

Две вещи из вчерашнего журнала оказались неточными, и обе меняют список долга.

1. **«Текст обрывается посреди строки, многоточия нет» — неверно.** Многоточие
   есть: `.portfolio-mosaic__item p` содержит `-webkit-line-clamp: 2` вместе с
   `display: -webkit-box` и `-webkit-box-orient: vertical`, то есть рабочий
   clamp. Кадр `.night-shots/mosaic-card.png` это показывает: «…работал со…».
   Причина моей ошибки — метрика `clipY` в `tests/text-geometry.test.ts`
   засчитывает любое `overflow: hidden/clip` + `scrollHeight > clientHeight` и не
   различает «обрезали случайно» и «обрезали намеренно, с многоточием». Все 23
   (и 42, см. ниже) найденных `clipY` — это **намеренный clamp в 2 строки**, а не
   поломка. Долг в другом: политике «2 строки» против решения §0.2 «3 строки».
2. **`clipY` не 23, а 42.** Храповик отсекает элементы ниже
   `innerHeight + 4000` (`vis()` в том же тесте), то есть на длинных страницах
   смотрит только верх. С снятым вырезом (`r.top > innerHeight + 100000`,
   прогон `.night-shots/scratch/geometry-nocut.mts`):

   | метрика | видит храповик | на самом деле |
   |---|---|---|
   | `clipY` | 23 | **42** |
   | `offscreen` | 12 | 12 |
   | `lines`, `overlap`, `clipX` | 0 | 0 |

   Правка в тесте — одна строка, но baseline после неё удваивается, поэтому не
   делаю: это решение того, кто принимает храповик. Полный список нарушителей без
   выреза — `/tmp/text-geometry-full.txt` (19 пар «маршрут@ширина»).

## 1. Обрезанные описания: одно правило на все 42

**Файл:** `src/v3-polish.css:254`

```css
.portfolio-mosaic__item p { max-width: 42ch; display: -webkit-box; margin: 0;
  overflow: hidden; color: rgba(244,244,239,.7);
  font: 400 .75rem/1.35 var(--ds-font-mono);
  -webkit-box-orient: vertical; -webkit-line-clamp: 2; }
```

Откуда берётся «фиксированные 32px»: это не `height`, а clamp. Кегль
`.75rem` = 12px, leading 1.35 → 16.2px на строку, две строки = **32.375px**
(столько и показывает `getComputedStyle(p).height`). `scrollHeight` при этом
49px (3 строки) или 65px (4 строки) — ровно те «49→32» и «65→32» из списка
нарушителей.

Затронутые маршруты (из замера без выреза): `/`, `/portfolio`,
`/portfolio/{post,events,broadcast,commercial,interviews,color,product}` —
на 1440 и на 390. Карточек в мозаике на `/portfolio` 20, из них с полным текстом
длиннее двух строк — 6; правка меняет вид ровно у них.

## 2. Рецепт под решение §0.2 («до 3 строк, дальше многоточие, карточка растёт»)

**Минимальная правка — одна цифра в `src/v3-polish.css:254`:**

```css
-webkit-line-clamp: 3;   /* было 2 */
```

Замерено после применения (тот же браузер, `addStyleTag`, без пересборки):

| что | было | стало |
|---|---|---|
| высота `p` | 32.375px | 48.5625px (3 строки) |
| высота карточки мозаики на 1440 | 653px | **653px** |
| высота карточки мозаики на 390 | 278px | **278px** |
| зазор до строки `small` («МОНТАЖ // ЦВЕТ // ЗВУК») на 390 | 5px | 5px |

То есть «карточка растёт по высоте» для мозаики **не произойдёт**: высота ячейки
задана сеткой (`design-system.css:1497–1503`, `grid-row: 1 / span 2` и т.д.), а
текст прижат к низу и растёт **внутрь** себя, вверх, в область градиента
(`.portfolio-mosaic__item::after`, `design-system.css:1503`). Это хорошо —
мозаика не разъедется, — но значит, что запас ровно один: 4 строки уже упрются в
`small`. Проверять надо на 390, там колонка уже.

**Чего clamp не делает: «многоточие по слову».** На кадре
`.night-shots/p-clamp3.png` (2× зум) третья строка читается
«…приводил материал к утверждённо…» — слово «утверждённости» разрезано, а
многоточие стоит внутри него. Это поведение `-webkit-line-clamp`: последняя
разрешённая строка обрезается по краю бокса, перенос слова на новую строку не
пробуется. Если «по слову» обязательно, резать надо в данных, то есть в
`src/public/PortfolioSystem.tsx:162` (там `project.description` попадает в
разметку) — ограничением по словам + «…», а clamp оставить как страховку от 4+
строк. Файл React — решение и правка за Claude Code.

## 3. Заголовок ГРК уезжает за край: 1480px при вьюпорте 1440

Виновник — не текст и не сетка страницы, а **мин-контент одного слова**.

```
.portfolio-featured__info  (a, overflow: hidden)   1004..1411   407.578px
└─ .portfolio-project-info (div, flex column, padding 34.56px)   контент 338px
   └─ div (flex-айтем, min-width: auto)             1038..1480   441.547px  ← вылез
      └─ h3 «Концерты «Станции метро Горьковская»»  57.6px, uppercase
```

Цепочка: `.portfolio-project-info h3` (`src/design-system.css:1476`) получает
`font: 800 clamp(2rem, 4vw, 5rem)/1` → на 1440 это **57.6px**, и самое длинное
слово «ГОРЬКОВСКАЯ» в min-content занимает **441.5px**. Блок-наследник в flex
колонке с `min-width: auto` не может стать уже своего min-content, поэтому
растягивается до 441.5px при доступных 338px и высовывается за правый край
панели на 69px; `.portfolio-featured__info { overflow: hidden }`
(`src/v3-polish.css:229`) ровно то, что отрезает и закрывающую кавычку, и
последнюю букву. `small` «монтаж // мультикам» в списке нарушителей — тот же
растянутый `div`, он наследует его ширину.

Ключевая деталь: в правиле уже стоит `overflow-wrap: break-word`, и она **не
помогает** — `break-word` разрешает рвать слово при переносе, но не участвует в
расчёте `min-content`. `overflow-wrap: anywhere` участвует.

**Рецепт (одна правка в `src/design-system.css:1476`):**

```css
overflow-wrap: anywhere;   /* было break-word */
```

Замерено: правый край `h3` **1480 → 1377** (панель кончается на 1411), заголовок
весь в кадре — кадр `.night-shots/grk-card-after.png`; высота карточки не
изменилась, `document.scrollWidth` остался 1440. Побочный эффект виден на том же
кадре: закрывающая кавычка «» падает на пятую строку одну. Если это некрасиво —
варианты: `text-wrap: pretty` рядом, или чуть меньший кегль в узкой колонке
(`clamp(2rem, 3.2vw, 3.4rem)` даёт 46.08px и та же картина без вылета), но кегль
заголовков — это тип-ритм, а §0.2 смены QWEN-06 прямо говорит его не трогать.

Затронутые маршруты: `/portfolio`, `/portfolio/{post,events,broadcast,concerts}`
на 1440 и на 390 — везде, где в каталоге есть `.portfolio-featured` с этим
проектом (12 узлов = 6 маршрутов × 2 ширины, по два узла: `h3` и `small`).

## 4. Порядок приёмки для Claude Code

1. Правка → `npm run build`.
2. `npx tsx scripts/style-fingerprint.ts --label до` (до первой правки) /
   `--label после` / `--diff до после` — с 89a3aa2 снимок видит и ритм текста
   (`fontSize`/`lineHeight`/`letterSpacing`), поэтому clamp в 3 строки он покажет
   как расхождение **намеренное**; всё остальное должно остаться нулём.
3. `npx tsx scripts/visual-diff.ts capture --label после && npx tsx
   scripts/visual-diff.ts compare --a до --b после` — ожидание: отличия ровно на
   перечисленных выше маршрутах, ноль на остальных.
4. `npx tsx tests/text-geometry.test.ts --write` — переснять baseline **осознанно**
   после правки: `clipY` изменит состав (те же 42, но уже «3 строки»), а если
   снимать вырез `vis()`, то и количество.
