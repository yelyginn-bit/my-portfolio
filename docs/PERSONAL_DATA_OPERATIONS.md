## Роли и доступ

- Публичный браузер не пишет напрямую в CRM-таблицы Supabase.
- Серверные endpoints валидируют запрос и используют service role.
- Клиентская сессия ограничивает данные владельцем `user_id`.
- Администратор использует короткую серверную сессию; секреты не хранятся в браузере.
- Административные комментарии по чекам клиенту не возвращаются.

## Запрос субъекта

1. Зарегистрировать запрос с датой, каналом и требованием.
2. Разумно подтвердить личность по уже имеющемуся контакту без сбора лишних документов.
3. Найти данные по нормализованному контакту/хешу.
4. Определить законные основания продолжения хранения.
5. Уточнить, выгрузить, ограничить или удалить доступные данные.
6. Для отзыва заполнить `withdrawn_at` в `consent_events`; дальнейшие заявки требуют нового согласия.
7. Сообщить результат заявителю и сохранить минимальный журнал выполнения.

## Инцидент

Ограничить доступ, сохранить технические факты без публикации секретов, оценить затронутые категории и субъектов, выполнить применимые обязанности по уведомлению, устранить причину и задокументировать меры.
