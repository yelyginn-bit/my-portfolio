## Шаг ноль

`git merge main` дал **один конфликт** — и это был не замороженный файл, а
`tests/fixtures/css-literals-baseline.json`: сгенерированный счётчик литералов.
По инструкции QWEN-05 §1 надо было `--abort` и работать только В/Д/Е, но
`--abort` отбросил бы ветку к состоянию до `a53b2c4`, а baseline задачи Д по
условию снимается именно после него — то есть откат ломал бы больше, чем
оставлял риска. Решил так (`05fc258`):

1. в файле остался вариант `main` (ничего рукописного там быть не может);
2. baseline перегенерирован инструментом по слитому коду (`0057fad`) —
   расхождение было ровно одно и предсказуемое: `public/site-skin.css`
   color 58 → 42, это снижение, сделанное в QWEN-04; сторона main про него не знала.

Если это читается как отклонение от §1 — откатить легко: два последних коммита
до очередей, `git revert 0057fad 05fc258`.

Проверка приёмки: в `main` есть `a53b2c4` (ручка «до/после» в цветокоррекции) и
`51f6586` (регрессии деплоя 23893b9: шапка, «Услуги», наложение строк, бегущая
строка, YELYGINN). Обе правки Claude Code касаются `src/design-system.css`,

конфликтов по содержимому нет.

## Порядок работ и почему он такой

Решения владельца из §0 принят: хром не токенизируем (умрёт вместе с пилюлей),
оранжевый как текст не трогаем, метку не ставим. Очередь идёт так:
**В → А → Б → Г → Д → Е** — инструменты первыми, потому что В2 (ключ отпечатка
по пути в DOM) — это ровно та причина, по которой QWEN-04 дала ложное «можно» и
чуть не уронила тёмную тему; без неё А и Г проверялись бы прежним
инструментом.
