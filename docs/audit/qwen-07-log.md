Две вещи, которые по ходу дела оказались важнее самой чистки:

1. **Гард на комментарии поймал настоящую ошибку разбора.** Начало правила
   бралось от позиции сразу после предыдущей `}` — то есть пустые строки и
   комментарий над селектором входили в вырезаемый диапазон. Из-за же этого
   номера строк в TSV уезжали на 2–3 строки вперёд. Поправлено в
   `dead-selectors.ts` и в вырезателе: старт — первый не-пробел буфера.
2. **Коммит `b790651` ушёл с красным `npm run check`** — в `dead-selectors.ts`
   остались незаполненные поля `start/end` из чёрновика, typecheck падал.
   Возвращено в зелёное состояние следующим коммитом `156c8da`. Порядок
   «сначала `&&`, потом коммит» нарушен мной же, записываю, чтобы не
   повторялось: `git add … && git commit` после `npm run check | grep` не
   останавливает цепочку, когда grep ничего не нашёл, — надо проверять код
   возврата самого check.
