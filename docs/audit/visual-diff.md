# Скриншот-сравнение страниц (`scripts/visual-diff.ts`)

Числовые проверки (`tests/text-geometry.test.ts`, `tests/mobile-audit.test.ts`,
`tests/dark-static-contrast.test.ts`) ловят то, что в них заложено. Этот
инструмент сравнивает **картинку до и картинку после** и показывает всё
остальное — включая изменения, про которые никто не подумал как про метрику.
Сделан для QWEN-05 §3 Е, чтобы его же использовал Claude Code при приёмке.

## Запуск

```bash
npm run build
npx tsx scripts/visual-diff.ts capture --label до
# …правка…
npm run build
npx tsx scripts/visual-diff.ts capture --label после
npx tsx scripts/visual-diff.ts compare --a до --b после
```

Проверить стабильность самого инструмента (два прогона одного кода):

```bash
npm run build
npx tsx scripts/visual-diff.ts capture --label a
npx tsx scripts/visual-diff.ts capture --label b
npx tsx scripts/visual-diff.ts compare --a a --b b --tolerance 0.05
```

Замерено 25.09 (QWEN-05 §3 Е): два полных прогона одного и того же кода —
**140 из 140 кадров идентичны, 0.000%**. До этого было 138 из 140:
`/photo@1440` и `/ceny@390` плавали на 0.17–0.40%, причина — догрузка
ленивых картинок в момент съёмки (у `/photo` 63 из 64 изображений с
`loading="lazy"`), лечится ожиданием `.complete`, см. ниже.

`--only <подстрока>` — снять не все 70 маршрутов, а часть (быстро проверить
одну страницу): `capture --label probe --only /photo`.

Кадр — вся страница целиком (`fullPage`), 1440 и 390, все 70 публичных
маршрутов из `routeManifest.ts` = 140 файлов на съёмку. Данные в
`.night-shots/visual/<метка>/` — вне git (исключение в `.git/info/exclude`),
одна съёмка ~50 МБ.

## Что делает кадр сравнимым

- **Перед съёмкой страница прокручивается до конца и обратно**, ждёт ~0.5 с.
  Секции V3 раскрываются по скроллу: без этого два кадра одного кода
  отличались бы ниже первого экрана, и это выглядело бы как регрессия правки.
- **Ждём `document.fonts.status === "loaded"` и `.complete` у всех картинок.**
  Без второго кадр не повторяется: на `/photo@1440` два прогона одного и того же
  кода отличались на 0.17–0.40% при идентичном DOM (63 из 64 картинок с
  `loading="lazy"` догружались в момент съёмки). После ожидания — 0.000%.
- **Маска.** Бегущая строка, `<video>`, `iframe`, постеры, картинки и
  `[class*='thumb']` закрашиваются константой **в обоих** кадрах перед
  сравнением: их пиксели от одного прогона к другому разные по определению.
  Координаты берутся на месте съёмки и лежат рядом —
  `.night-shots/visual/<метка>/masks.json`. Проценты считаются по площади
  **вне** маски, поэтому «2%» означает 2% полезного кадра, а не 2% картинки,
  половина которой — видео.
- Разница ниже допуска (`--tolerance`, по умолчанию 0.05%) не пишет diff-кадр;
  выше — пишет в `.night-shots/visual/diff-<a>-<b>/<маршрут>@<ширина>.png`,
  где изменённые пиксели подсвечены красным.

## Выход

`compare` печатает таблицу «маршрут → % изменённых пикселей», отсортированную
по убыванию, и возвращает ненулевой код, если хотя бы один маршрут выше
допуска. Полностью отличается строка с пометкой «размер кадра …» — это значит,
что у страницы изменилась высота или ширина (переполнение, перенос, другой
число строк): пиксельное сравнение тут бессильно, и это надо смотреть глазами.

## Чего инструмент НЕ проверяет

Не понимает, «хорошо» или «плохо» изменение: он отвечает только «что
отличается». Ответственность за смысл — за тем, кто дифф смотрит. Второй
момент: он сравнивает сборки, а не «живой сайт с прошлой неделей» — базовый
кадр надо снимать на том же коммите, на котором стоит правка.
