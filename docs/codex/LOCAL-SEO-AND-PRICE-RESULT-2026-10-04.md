## Кодовая диагностика health 503

После релиза GET production `/api/health` повторно проверен: HTTP 503 с `database=false`, `telegram=true`, `adminAuth=false`, `storage=false` (ответ от 04.10.2026 18:13 МСК). Код `/api/health` делает общий результат 503, если любое из четырёх условий ложно: доступ к таблице настроек БД, наличие Telegram token + chat ID, наличие admin/JWT секретов, конфигурация Supabase Storage или R2. Поэтому общий 503 сам по себе не доказывает, что публичная форма не может отправить Telegram.

Путь формы проверен в исходнике: отдельная причина 503 — ошибка обязательной записи согласия в БД, включённый `REQUIRE_CONSENT_JOURNAL` без доступной БД или отсутствие Telegram credentials. Ошибка реальной доставки через relay/Telegram возвращает 502. `telegram=true` означает наличие конфигурации и не проверяет успешную доставку. Ранее владелец подтвердил получение помеченной тестовой заявки; нового тестового обращения не отправляли. В рамках этого релиза runtime-конфигурация не менялась.

Чтобы определить runtime-причину текущего состояния, нужен свежий ответ health вместе с просмотром только имён (не значений) переменных Vercel и соответствующих логов backend `yelyginn-v3`. Зелёный статус нельзя получать отключением проверок.
