# Инвентаризация публичных страниц перед переводом на тёмную тему

**QWEN-01 · только чтение · 24.09.2026 · ветка `qwen/site`**

Задача: карта работ перед фазой 5 (`docs/SITE-HANDOFF.md`, «Тёмная тема: как
перевести следующую страницу»). Для каждой публичной страницы, которая ещё не
тёмная, — что на ней придётся менять. Код сайта не менялся; единственный
созданный файл — этот отчёт.

## 0. Метод и границы проверки

**Список страниц** взят из `src/public/routeManifest.ts` → `INDEXABLE_ROUTES`
(из них собирается `scripts/sitemap.ts`, т.е. это и есть «публичные в sitemap»).
Всего 70 маршрутов; тёмная одна — `/video-dlya-marketpleysov`
(`src/public/routeManifest.ts:38`, поле `theme: "dark"`). К переводу **69**.

**Что считается находкой** (пункты §2 промпта):

| Счётчик | Что попадается | Что НЕ попадается |
|---|---|---|
| цвет-литерал | hex / `rgb()` / `rgba()` в правилах | объявления `--токенов` (`--ds-*`, `--site-*`), `transparent`, `currentColor`, строки в комментариях |
| radius≠0 | `border-radius` конкретным числом | `0` и значения через `var(--ds-radius*)` |
| font-family | литеральное семейство | `var(--ds-font-*)`, `inherit` |
| свой `:root` | локальный блок, заново объявляющий палитру | — |
| легаси-var | обращения `var(--black)`, `var(--site-bg)`, `var(--red)` | считаются **долгом имени**, а не хардкодом цвета: `public/site-skin.css:9-40` уже маппит эти имена на `--ds-*` |

**Как литералы относились к странице.** Общие таблицы стилей (`design-system.css`,
`v3-polish.css`, `index.css`, `site-skin.css`, `legal.css`) подключаются к
разным страницам по-разному, поэтому для каждого маршрута проверялись две вещи:
(1) какой файл страница действительно грузит — по `input` в `vite.config.ts`,
по `<link>` в каждом HTML-входе и по строкам `import '*.css'` в каждом
`src/*/main.tsx`; (2) рендерит ли страница классы из селектора правила — по
фактическому SSR-размету всех 70 маршрутов (`react-dom/server`, тот же путь,
что в `scripts/prerender.ts:134`). Правило считалось живым для страницы, только
если **все** уровни составного селектора присутствуют в её разметке; группы
`:is()` / `:has()` — как «любое из».

Это важно, потому что иначе числа выходят кратно больше реальных: во всём
`src/design-system.css` 234 строки с литералами, но после отсечения мёртвых
селекторов живых литералов остаётся 172 на все страницы сразу. Разница — §6.4.

### Чего я НЕ проверял

- **Вычисленный стиль (`getComputedStyle`) на живой или собранной странице.**
  В `docs/SITE-HANDOFF.md:452-455` прямо записано, что в этом проекте
  «объявленное не доходит до рендера» и решать надо по вычисленному стилю.
  Браузерного доступа в этом заходе не было, live-сайт я не открывал.
  Все выводы ниже — по исходнику. Выводы о каскаде, помеченные ⚠️, перед
  правкой обязан подтвердить `getComputedStyle`.
- **Контраст пар «цвет на фоне»** — это §5 инструкции к переводу, не инвентаризация.
- **Мобильные брейкпоинты отдельно от десктопа**: литералы посчитаны по всем
  правилам файла, включая `@media`; построчная разбивка «на 390px» не делалась.
